# Six-phase roadmap

1. **Foundation, authentication, patient registration/search — implemented.** Local Django/SQLite, Owner and Doctor roles, validated demographics, normalized phone search, duplicate selection, profile Overview, audit foundation and offline responsive interface. Review fixes add international partial-prefix matching, bounded private diagnostics and isolated GitHub Actions checks. Existing desktop shortcut/Windows trial launchers remain available.
2. **Visits, medical history, dental chart, treatments, attachments — implemented trial.** Dated visits, revision-safe autosave, completion/amendments retaining originals, per-visit medical snapshots, adult/primary FDI chart, editable no-price procedure examples, staged plans spanning visits, private originals/thumbnails and validated JPEG/PNG/passive-PDF uploads. Additive migrations preserve existing records; a verified database/secret safety copy precedes local migration. Unit/integration and real-browser desktop/narrow checks use fictional data. This does not establish live clinical readiness or complete backup recovery.
3. **Charges, payments, installments, outstanding balances - implemented trial.** Exact financial arithmetic and auditable corrections. Doctor can see every individual patient's entire financial history, including old fully paid accounts, today's combined collections and outstanding individual balances. Owner alone sees combined historical totals and weekly/monthly/annual reports. Deny bulk financial export to Doctor. Test every report boundary server-side.
4. **Appointments, next-patient panel, tasks, prescriptions - implemented trial.** Versioned bookings, overlap confirmation/history, arrived queue and overdue visibility, idempotent visit linkage, private task carry-forward/history, Doctor-authored drafts and immutable issued prescription snapshots with void/replacement history, white prints, configurable identity and manual reminders. Owner-only prescribing is denied; financial role boundaries remain unchanged.
5. **Backups, restore, transfer, migration exports - implemented trial; stop here.** Owner centre, coordinated complete encrypted SQLite/original/thumbnail/secret packages, authenticated verification, daily in-process scheduler/DPAPI, per-destination results/retention, existing Drive-folder support without cloud-upload claims, offline staged restoration/rollback/journal repair and encrypted credential-free migration exports. Isolated fresh-directory recovery and original logins/relationships/checksums verified. Physical off-device/cloud/power-loss and clinic trials remain unverified; separate-device copy is required.
6. **Full verification, interface polish, Windows startup packaging.** Fictional-data clinic trial, representative-volume performance, accessibility and complete role checks; recovery drills, startup/shutdown/restart behavior and reliable localhost Windows installation. Resolve operational risks and sign off before entering real patient data. `runserver` is not the finished installation.

Online deployment/PostgreSQL is a separately planned future stage, with HTTPS, secure cookies, operational monitoring, migration and hosting security work. No online application deployment is included. Exact next step: await explicit Phase 6 authorization for final packaging and operational clinic/recovery trials. Phase 5 has an isolated verified recovery drill; this does not establish physical off-device protection, power-loss resilience or live clinic readiness. Phase 3 includes immutable transaction/correction history, installments, outstanding workspace, today collections, Owner range reports/expenses/CSV and private receipts. Historical receivable snapshots, production volume/recovery trials and physical printer validation remain outstanding. Continue fictional data only until Phases 5–6 gates pass.
