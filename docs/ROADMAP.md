# Six-phase roadmap

1. **Foundation, authentication, patient registration/search — implemented.** Local Django/SQLite, Owner and Doctor roles, validated demographics, normalized phone search, duplicate selection, profile Overview, audit foundation and offline responsive interface. Review fixes add international partial-prefix matching, bounded private diagnostics and isolated GitHub Actions checks. Existing desktop shortcut/Windows trial launchers remain available.
2. **Visits, medical history, dental chart, treatments, attachments — implemented trial; stop here.** Dated visits, revision-safe autosave, completion/amendments retaining originals, per-visit medical snapshots, adult/primary FDI chart, editable no-price procedure examples, staged plans spanning visits, private originals/thumbnails and validated JPEG/PNG/passive-PDF uploads. Additive migrations preserve existing records; a verified database/secret safety copy precedes local migration. Unit/integration and real-browser desktop/narrow checks use fictional data. This does not establish live clinical readiness or complete backup recovery.
3. **Charges, payments, installments, outstanding balances.** Exact financial arithmetic and auditable corrections. Doctor can see every individual patient's entire financial history, including old fully paid accounts, today's combined collections and outstanding individual balances. Owner alone sees combined historical totals and weekly/monthly/annual reports. Deny bulk financial export to Doctor. Test every report boundary server-side.
4. **Appointments, next-patient panel, tasks, prescriptions.** Implement the reserved right panel, daily appointment workflow and personal tasks, prescribing and appropriate printable documents. No fake placeholders treated as live features.
5. **Backups, restore, transfer, migration exports.** Implement the complete backup contract in REQUIREMENTS.md: consistent database/attachments snapshot, manifest/schema version, encryption, integrity verification, dated retention, local/external targets, optional online Google Drive upload and independently verified restores. Owner-only export/restore. Separate-device copy required.
6. **Full verification, interface polish, Windows startup packaging.** Fictional-data clinic trial, representative-volume performance, accessibility and complete role checks; recovery drills, startup/shutdown/restart behavior and reliable localhost Windows installation. Resolve operational risks and sign off before entering real patient data. `runserver` is not the finished installation.

Online deployment/PostgreSQL is a separately planned future stage, with HTTPS, secure cookies, operational monitoring, migration and hosting security work. No online application deployment is included. Exact next step: wait for explicit Phase 3 authorization, then implement charges/payments/installments/balances with the stated financial role boundaries. Continue fictional data only until Phases 5–6 gates pass.
